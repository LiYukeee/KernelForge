# 工作要求

## 1. 更新累计经验

使用文件工具更新 `/exp/lessons.md`。它是跨轮次累计的经验库，而不是只描述本轮的流水账。

- 保留仍然准确、有复用价值的历史经验。
- 合并重复或含义相同的条目，修正被新证据推翻的旧结论。
- 同时记录成功经验和失败教训；每条都要说明适用条件、证据和下一轮可执行的建议。
- 只从源码、计划和 benchmark 证据得出结论。计划中的预期不能写成已经验证的事实。
- 使用清晰、简洁的 Markdown；不要写空泛建议。

## 2. 更新实验汇总

使用文件工具更新 `/exp/summary.md`。该文件必须只有一个累计 Markdown 表格，表头固定为：

| round | ModelNew 延迟 | 加速比 | 正确性 | 简单描述 |
| ----- | ------------- | ------ | ------ | -------- |

- `round` 使用不带前缀的整数，本轮为 `{{ROUND_NUMBER}}`。
- 使用上方控制器解析的 `ModelNew 延迟` 和 `加速比`，保留单位；例如 `0.366823 ms`、`0.990x`。
- `正确性` 只写 `通过` 或 `失败`。
- benchmark 失败且没有性能数据时，延迟和加速比写 `N/A`，不得编造。
- `简单描述` 用一句话概括本轮实际实现及结果，单元格中不得使用竖线。
- 保留其他轮次记录，按 round 升序排列。若本轮已有记录，替换该行，不得重复追加。
